# UART2UART 2.0 双 RS-485 验证与部署记录

日期：2026-09-03。原 1.0 测试记录保留在 TEST_REPORT.md，本文件记录本次更新。

## 原因与硬件依据

1. 检查原运行界面及开发板进程文件描述符，旧程序打开的是 `/dev/ttymxc6`。
2. 板卡软件教程 156～157、429 页确认：A1/B1 = UART2 = `/dev/ttymxc1`；A2/B2 = UART3 = `/dev/ttymxc2`；`ttymxc6` 是 UART7 / RS-232。
3. 原程序一个实例只打开一个端口，不能同时监听同板另一个接口。
4. 用户确认 A1→A2、B1→B2。硬件教程 PDF 第 44 页（印刷页码 43）的原理图显示两路 MAX13487E 自动选向收发器，不需要软件 GPIO 方向控制。
5. 运行中的内核已有 `ttymxc1`、`ttymxc2`，不是缺驱动。本次不修改驱动、设备树或系统控制台。

## 程序改动

- 新增 DualPanel：两个独立 SerialSession、两侧真实 RX 显示及各自 TX/RX 计数。
- 默认填入原厂 ELF1 的两个 RS-485 节点；明确禁止双口页打开 `ttymxc0` 控制台。
- 同一端口拒绝双开；第二端口打开失败回滚第一个；任一端口断开时关闭双口。
- “验证 1→2 / 2→1”发送唯一字符串，只有对侧真正收到完整字符串才判定通过；单纯本端回显不能通过验证。
- 手动单次发送、UTF-8/HEX、半双工发送间隔保护、约 3 秒验证超时；无自动回显、无自动发送。
- AppWindow 保留原单口工具页；活动模式打开串口时禁止切换另一模式，防止内部端口抢占。
- 新增 rs485check 命令行硬件验收工具，要求显式指定两个存在且不同的非控制台端口。

## 实际开发板收发结果

目标：`192.168.0.232`，ELF1。
端口：`/dev/ttymxc1` ↔ `/dev/ttymxc2`，115200 / 8N1 / 无流控。

在用户确认的 A1→A2、B1→B2 接线上执行 `rs485check`：

- 10 次交替方向发送全部通过，每方向 5 次。
- 前两次测试唯一字符串，后八次额外包含全部 256 种字节值（00～FF）。
- 每次对侧收到的数据均按完整字节序列比较，不是只检查发送字节数。
- 测试进程退出后释放两端口。

原始结果：`board-rs485-test-log.txt`，末行 `ALL_10_TRANSFERS_PASSED`。

随后在真正运行于开发板、经 MobaXterm X11 显示到 Windows 的新版界面中，分别点击两个方向的验证按钮；两个方向都显示通过，左右接收区分别显示对侧发送的唯一字符串。

这些测试证实当前两路接口在此次短线测试条件下正常，不代表长线、多节点、长期满负载环境已验收。开发板系统时钟与当前日期不一致，因此板上日志显示旧日期/时间，本次没有修改其时钟。
